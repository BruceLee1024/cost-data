# 造价数据库管理平台 UI 生成提示词

请为以下产品设计一套可落地的高保真桌面 Web 应用 UI。不要生成营销官网、落地页或概念展示图，要生成一个真正可操作的专业数据工作台，并覆盖核心页面和关键交互状态。

## 产品定义

产品名称：个人造价数据库管理平台

这是一个面向单人工程造价师、在个人电脑本地运行的 AI 辅助造价数据管理工具。它把数百个历史工程项目中的广联达及其他 Excel 报表，转化为可检索、可比较、可追溯、可复用的个人造价数据库。

产品的核心价值不是“AI 自动给答案”，而是帮助用户快速找到历史清单、定额、工料机和价格数据，比较综合单价组成，为新项目清单匹配多个历史参考价，并让每个结果都能追溯到原始项目、Excel 文件、工作表和单元格。AI 只负责提供候选、解释和建议，最终决定始终由用户确认。

目标用户是熟悉广联达和 Excel 的中国工程造价师。用户会在 13 至 16 英寸笔记本上长时间、高频处理大量表格，重视效率、准确性、可比口径和数据来源。

## 设计目标

界面气质应当专业、可靠、克制、清晰，像现代化的造价工作台，而不是通用 AI 聊天产品或传统臃肿工程软件。

设计必须遵守以下原则：

1. 证据先于结论：价格、指标、匹配结果和 AI 建议都可以就地查看来源、口径、计算过程和版本。
2. 异常优先：导入和匹配流程只突出需要人工判断的少量异常项，正常数据批量通过。
3. 熟悉但更清晰：保留造价人员熟悉的表格、树形层级、筛选器和批量操作，但减少工具栏堆叠和无效层级。
4. 对比辅助决策：差异、风险、置信度和不可比原因应比单一推荐结果更醒目。
5. AI 与事实严格分层：历史原始值、系统计算值、规则匹配值、AI 建议必须使用文字标签和图标明确区分，不能只靠颜色区分。
6. 本地可信：在合适位置展示“仅本机”“原始文件只读”“云端发送范围”等状态，但不要反复宣传。

## 整体布局

以 1440 × 900 为主要设计画布，同时适配 1280px 宽笔记本；这是桌面优先产品，不需要设计手机端。

- 使用稳定的应用外壳：左侧 216px 导航栏，顶部 52px 全局栏，中间为高密度工作区。
- 左侧导航分组：工作台、项目库、数据查询、清单匹配、价格对比、导入任务；下方为个人规则、备份与恢复、设置。
- 顶部栏包含全局搜索、后台任务状态、本地数据状态和用户入口。不要放冗余欢迎语。
- 页面主体使用可调整宽度的筛选侧栏、数据表格、详情面板和右侧抽屉。不要把每个页面区块都包成悬浮卡片，也不要出现卡片套卡片。
- 表格是核心视觉元素：表头固定、列可调整、行高约 36px、支持排序、列筛选、多选、批量操作、列显隐和虚拟滚动。
- 长层级数据用树形表格；细节和来源用不遮挡主任务的右侧抽屉；复杂确认使用明确的分步流程。

## 视觉语言

- 背景以中性浅灰和白色为主，正文使用近黑色，边界清楚但不过重。
- 主操作色使用沉稳的深绿色；蓝色只用于信息和链接；琥珀色表示待确认；红色表示错误或高风险；灰色表示停用或不可用。整体不要被单一色系支配。
- 不使用大面积渐变、玻璃拟态、发光效果、装饰性插画、巨型数字、超大圆角或夸张阴影。
- 卡片圆角不超过 6px，边框 1px，阴影极轻或不用阴影。
- 中文字体使用清晰的系统无衬线字体，数字价格使用等宽数字特性；标题克制，页面标题约 20px，正文 13 至 14px，表格 12 至 13px，字间距为 0。
- 图标使用统一线性图标；按钮优先采用图标加短文字。所有状态同时提供图标、文字和颜色。
- 图表只用于价格分布、组成对比和指标趋势，保持分析型而非装饰型。
- 满足 WCAG 2.1 AA，提供清晰焦点态、键盘操作、语义化表格，并兼容系统缩放和色觉差异。

## 默认首屏：数据查询与来源追溯

请优先完整设计“数据查询”页面，作为展示整套产品设计语言的主屏：

1. 页面顶部是一行组合查询区，左侧为自然语言输入框，示例内容为“近三年西安住宅项目中 C30 商品混凝土的价格和来源”，右侧是“查询”按钮和“结构化筛选”切换按钮。自然语言查询不是聊天窗口，不显示气泡对话。
2. 输入框下方展示已解析的可编辑条件标签：地区=西安、时间=2023—2026、项目类型=住宅、名称=C30 商品混凝土；旁边标记“AI 解析，尚未改变原始数据”。
3. 左侧筛选栏包含地区、价格基准期、专业、项目类型、成果阶段、计价体系、单位、可信程度、数据状态等折叠筛选项，并提供“清除条件”和保存筛选方案。
4. 中间主区首先显示紧凑统计摘要：共 42 条样本、涉及 11 个项目、原始价中位数 438.50 元/m³、区间 402.00—487.30 元/m³。摘要下方是价格分布小图，异常值可点击筛选。
5. 主表列包括：选择、原始名称、规格、单位、原始价、可比价、价格基准期、所属项目、专业、成果阶段、数据类型、可信程度、来源。价格右对齐并使用等宽数字。
6. 表格中使用真实、合理的中文造价样例，例如“预拌混凝土 C30 泵送”“商品砼 C30”，项目示例为“西安高新住宅一期”“曲江办公楼改造”。避免 lorem ipsum 和无意义占位数据。
7. 选中一行后，从右侧打开“证据与来源”抽屉，顶部明确显示“历史原始值”。抽屉依次展示：原始记录、项目背景、价格口径、来源链路、版本状态。来源链路格式为“西安高新住宅一期 > 招标控制价 V3 > 单位工程投标报价汇总表.xlsx > 工料机汇总!H126”，提供“定位原始文件”按钮。
8. 若存在可比价，抽屉中同时展示原始价、换算结果、公式、参数、依据来源、换算时间和适用范围；若依据不足，则明确显示“不可自动换算”及原因。
9. 勾选 2 至 5 行后，页面底部出现固定批量操作栏，可执行“加入对比”“导出所选”“保存为样本集”。

## 其他核心页面

### 1. 工作台

首屏不是营销式欢迎页，而是今日工作概览。展示正在运行的导入任务、待处理异常数量、最近项目、最近保存的查询和备份状态。突出“继续处理 23 个导入异常”和“导入历史项目”两个实际动作。

### 2. 项目库与项目详情

项目库使用表格而非卡片墙，支持按地区、专业、阶段、价格基准期和版本状态筛选。项目详情使用页签：概览、清单、综合单价分析、定额、工料机、措施费、指标、源文件、版本。概览展示总造价、建筑面积、单方造价、钢筋含量、混凝土含量；每项指标都能展开公式、分子来源、分母口径和校验差异。版本页展示正式稿、过程稿、作废稿及版本差异，不覆盖旧版本。

### 3. 导入向导、任务与质量报告

导入流程为：选择项目文件夹 → 文件与报表识别 → 确认项目元数据 → 质量检查 → 发布。使用清晰的步骤条和后台任务进度，允许用户离开页面后继续运行。

质量报告顶部显示“可直接发布 96.8% / 待确认 23 项 / 阻断错误 4 项”，下方按异常类型分组：关键字段缺失、单位冲突、关联失败、疑似重复、金额不平、低置信度识别。主区域是异常表格，右侧并排显示原 Excel 行片段和系统解析结果。提供批量应用修正、仅处理异常、保存为模板规则、重新校验。完全相同的重复文件标记为“已跳过”，变化文件标记为“将创建新版本”。

### 4. 清单匹配工作台

页面采用三栏决策布局：左侧为新项目清单树和处理进度，中间为当前清单项及多个历史候选，右侧为候选证据和价格组成。

顶部显示“已确认 128 / 待处理 36 / 无可靠候选 7”。当前清单项展示编码、项目名称、项目特征、单位和工程量。候选列表必须同时显示匹配程度、匹配理由、不一致项、历史原始价、可比价、项目背景和来源，不只显示一个黑盒百分比。

主要操作为“确认采用”“调整参考价”“拒绝候选”“稍后处理”。支持键盘快速切换下一项。低可信度项必须人工确认。用户确认后，可选择“仅本次使用”或“保存为个人规则”；保存长期规则前展示规则条件和影响范围预览。

### 5. 综合单价对比

顶部是已选择的 2 至 5 个样本摘要。主体先显示价格分布与差异提示，再使用横向对比表展示人工费、材料费、机械费、管理费、利润、风险及其他组成。下方用可展开树表对比关联定额子目、消耗量和主要材料价格。突出规格、单位、时间、地区、税率、计价口径不一致造成的“不可直接比较”原因。不要用雷达图；优先使用分组条形图、点图和对齐表格。

### 6. 个人规则

以可搜索表格管理名称标准化、单位换算、分类、匹配、禁止匹配和模板识别规则。列出规则来源、条件、动作、命中次数、最后使用时间、状态和影响范围。规则可查看、编辑、停用和删除；删除前显示影响预览。AI 建议的规则必须标为“待确认”，不能自动生效。

### 7. 备份与设置

展示最近备份时间、备份位置、数据库和原始文件完整性、恢复演练结果。操作包括“立即备份”“验证备份”“从备份恢复”。恢复是高风险操作，需要先校验备份并明确说明不会直接覆盖正在使用的数据。AI 设置展示供应商、模型、脱敏选项、发送前预览和调用记录；API Key 只显示已配置状态，不显示完整内容。

## 全局状态与交互细节

- 统一数据标签：历史原始值、系统计算值、规则匹配、AI 建议、用户确认值。
- 统一任务状态：等待、运行中、等待复核、成功、失败、已取消、中断可恢复。
- 统一可信度表达：高、中、低，并列出判断依据和不确定点；不能只展示百分比。
- 空状态要说明下一步实际动作，例如“尚未导入历史项目”，并提供“选择项目文件夹”。不要使用装饰插图。
- 错误信息必须说明影响范围和恢复方式；后台长任务支持取消、重试和断点恢复。
- 危险操作使用确认对话框；普通操作尽量就地完成，并提供撤销反馈。
- 所有页面都要包含加载、空数据、部分失败、无 AI 网络、只读、低可信度和超长文本等状态。
- AI 服务不可用时，结构化筛选、规则匹配、统计、来源追溯和导入流程仍然可用，界面应呈现明确但不打断工作的降级状态。

## 禁止出现

- 营销首页、巨型 Hero、宣传口号和产品功能介绍区。
- 以聊天机器人作为产品主界面。
- 大量独立圆角卡片、卡片嵌套、胶囊按钮和悬浮组件。
- 紫蓝渐变、霓虹效果、玻璃拟态、暗色科技大屏风格。
- 只有漂亮图表但缺乏表格、筛选、来源和确认操作。
- 把 AI 建议、原始历史价格和系统计算结果混为一谈。
- 用颜色作为状态的唯一表达方式。
- 不符合中国工程造价语境的英文占位文案或虚假数据。

## 输出要求

输出完整、统一、可实现的高保真 UI 方案，并优先展示“数据查询与来源追溯”主屏。至少补充工作台、项目库、项目详情、导入质量报告、清单匹配、综合单价对比、个人规则、备份与设置的关键页面或状态。

所有界面文案使用简体中文。使用合理的造价专业示例数据，让表格、筛选、异常、价格组成、可信度和来源链路真实可读。保持固定应用框架和一致的组件体系，设计需可由 React + TypeScript + TanStack Table 实现，不依赖难以落地的特殊视觉效果。
